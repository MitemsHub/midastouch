5. HARNESS DEFECTS FOUND WHILE DOING THIS (both fixed + pinned)
===================================================================
1. Reused run tags broke every research-line capture. `run_experiment` built
   the tag as `v28_<window>_<hypothesis>` — deterministic, so a re-run reuses
   the tag of an earlier pass in the same journal. `journal_has_tag()` searched
   the WHOLE file, matched the older line, and returned True immediately, so
   the bounded wait exited at once and the delta-based parse found nothing:
   all 32 passes reported "no RESEARCH_RESULT line captured".
   Fix: run tags now carry pid + timestamp (one tag = one pass), and
   `journal_has_tag(tag, snaps)` only searches bytes after the snapshot.
2. `cmd_backfill` used `re.search` and therefore took the OLDEST matching line.
   On this run it replaced the post-fix whole-run R with defect-era values on
   24 of 32 records — the first pass of this re-run was corrupted by it and had
   to be repaired. Its docstring claimed "the run tag is unique per pass",
   which was false.
   Fix: collect all matches and take the newest; tag uniqueness now makes the
   question moot. Both rules pinned by tests.
   The 32 records were then rebuilt from their own reports (OnTester result for
   R, Total Net Profit for P&L, deal reasons for the exit split), and the
   contaminated intermediate is kept as
   `registry_backfilled_contaminated_20260913.jsonl` for audit.
